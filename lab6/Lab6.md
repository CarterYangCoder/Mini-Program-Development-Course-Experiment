## 一、实验内容

本实验使用微信原生小程序框架和云开发能力，实现一个图片分享社区。用户可以浏览社区图片，按照作品标题、描述、作者和主题进行搜索，也可以登录后发布图片、完善个人资料、关注作者、收藏和点赞作品。

项目使用云数据库 `photos` 保存作品信息，使用云存储保存图片文件，并通过 `getOpenId` 云函数获取当前用户的 OpenID。主要功能如下：

1. 首页按上传时间倒序展示图片作品，并以双列瀑布流形式排列；
2. 支持自然、城市、人物、旅行、日常等主题筛选；
3. 支持按照作品标题、描述、作者昵称和分类进行关键词搜索；
4. 支持微信头像授权和昵称填写，完成用户登录；
5. 支持从相册或相机选择图片，填写标题、故事和主题后发布作品；
6. 支持作品详情查看、全屏预览、保存到相册和微信好友分享；
7. 支持收藏、点赞和关注作者，相关状态保存在本地缓存中；
8. 支持个人主页查看自己的作品、收藏作品和上传历史；
9. 作者可以在自己的作品详情页删除作品；
10. 使用云函数安全获取用户 OpenID，避免在客户端直接处理敏感身份信息。

## 二、实验步骤与关键实现

### 1. 项目初始化与页面配置

项目采用微信小程序原生目录结构，主要页面如下：

```text
miniprogram/
├─ pages/index/index       # 社区首页
├─ pages/homepage/homepage # 个人主页
├─ pages/detail/detail     # 作品详情
├─ pages/add/add           # 发布作品
├─ components/cloudTipModal # 云开发提示组件
├─ images/                 # 图标与界面资源
├─ app.js                  # 小程序全局配置与云环境初始化
└─ app.json                # 页面路由和窗口配置
cloudfunctions/
├─ getOpenId              # 获取当前用户 OpenID
└─ quickstartFunctions    # 作品删除等云端操作
```

`app.js` 中初始化云开发环境，并在小程序启动时调用 `getOpenId` 云函数：

```js
wx.cloud.init({
  env: "cloudbase-d4go8irco7551d927",
  traceUser: true,
});

wx.cloud.callFunction({ name: "getOpenId" })
  .then(({ result }) => {
    this.globalData.openid = result.openid;
  });
```

全局数据中保存当前环境、OpenID 和登录用户资料，用户资料同时写入本地缓存，以便页面切换后保持登录状态。

### 2. 首页作品展示与筛选

首页从云数据库 `photos` 集合中读取作品，并按照 `createdAt` 倒序排列：

```js
photos.orderBy("createdAt", "desc").limit(100).get()
  .then(({ data }) => {
    this.setData({ photoList: data });
    this.applyFilters();
  });
```

筛选逻辑同时处理关键词、主题标签、推荐/关注 feed 和本地收藏状态。关键词会匹配作品标题、描述、作者昵称及主题分类。筛选完成后，将数组按索引分为左右两列，形成双列瀑布流布局：

```js
leftColumn: filteredPhotos.filter((_, index) => index % 2 === 0),
rightColumn: filteredPhotos.filter((_, index) => index % 2 === 1),
```

首页还提供下拉刷新，重新读取云数据库后更新页面内容。

### 3. 登录与个人资料

用户点击登录后，程序首先获取 OpenID，再查询 `users` 集合中是否已有资料。首次登录时显示资料设置区域，用户需要选择微信头像并填写昵称。头像通过云存储上传，上传成功后将头像文件 ID 和昵称写入用户资料。

登录状态保存在 `photoCommunityUserInfo` 本地缓存中。退出登录时清除当前登录资料，但保留设备上的收藏和关注记录，方便用户再次登录后继续使用。

### 4. 图片选择与作品发布

发布页使用 `wx.chooseImage` 从相册或相机中选择一张图片，并允许用户预览或移除待发布图片。发布前需要完成登录、获取 OpenID 和图片选择。

图片上传流程如下：

1. 读取本地临时图片路径；
2. 生成带时间戳和随机字符串的云存储路径；
3. 调用 `wx.cloud.uploadFile` 上传图片；
4. 将图片文件 ID、头像、昵称、标题、描述、主题和发布时间写入 `photos` 集合；
5. 清空发布表单并刷新上传历史。

作品数据示例：

```js
{
  photoUrl: fileID,
  avatarUrl: userInfo.avatarUrl,
  nickName: userInfo.nickName,
  title: title.trim() || "未命名作品",
  description: description.trim(),
  category: selectedCategory,
  addDate: formatDate(new Date()),
  createdAt: db.serverDate()
}
```

### 5. 作品详情、保存与分享

详情页通过 URL 参数中的作品 ID 查询对应数据。用户可以查看图片、标题、作者、故事和主题信息，也可以进行以下操作：

- 调用 `wx.previewImage` 全屏预览图片；
- 从云存储下载图片并调用 `wx.saveImageToPhotosAlbum` 保存到相册；
- 使用 `onShareAppMessage` 分享作品详情页；
- 收藏或取消收藏作品；
- 关注或取消关注作者；
- 对自己发布的作品执行删除操作。

删除操作通过 `quickstartFunctions` 云函数完成，并在删除成功后同步清理本地收藏记录，避免再次进入详情页时出现无效收藏。

### 6. 本地缓存交互状态

项目将不需要实时同步到服务器的轻量交互状态保存在本地缓存中：

| 缓存键 | 用途 |
| :- | :- |
| `photoCommunityUserInfo` | 保存登录用户头像和昵称 |
| `favoritePhotoIds` | 保存当前设备收藏的作品 ID |
| `likedPhotoIds` | 保存当前设备点赞的作品 ID |
| `followedAuthorIds` | 保存当前设备关注的作者 OpenID |

收藏、点赞和关注操作使用 `wx.setStorageSync` 立即保存，页面进入 `onShow` 生命周期函数时重新读取缓存，从而保证页面切换和小程序重新启动后状态仍然能够恢复。

### 7. 个人主页

个人主页通过 OpenID 查询指定用户发布的作品，并按照发布时间倒序展示。当前用户的主页还提供作品和收藏两个分区：作品分区读取当前用户发布的图片，收藏分区根据本地保存的作品 ID 查询对应作品。

个人主页同时显示用户头像、昵称、作品数量和收藏数量。查看其他用户主页时，可以关注或取消关注该作者；查看自己的主页时，可以进入发布页面继续上传作品。

### 8. 界面设计与适配

页面整体采用浅灰背景、白色卡片和红色强调色，使用 `flex` 布局、圆角、阴影和图标增强移动端视觉层次。图片展示使用自适应尺寸，详情页强调大图和长文本阅读体验，首页使用瀑布流提高图片浏览效率。

## 四、问题总结与体会

### 1. 云端图片和数据库记录如何保持一致？

图片发布需要先上传文件，再把返回的 `fileID` 写入数据库。如果只上传图片而数据库写入失败，就可能产生无引用文件。因此发布流程中使用 Promise 串联上传和数据库写入，并在界面上显示上传中、成功和失败状态，便于用户重试。

### 2. 如何安全识别当前用户？

项目通过云函数获取 OpenID，客户端只保存云函数返回的身份标识，不直接构造用户身份。作品查询、个人主页和删除操作都使用 OpenID 进行判断，从而区分当前用户和其他用户。

### 3. 本地缓存和云数据库如何分工？

作品、作者和图片信息属于社区公共数据，保存在云数据库和云存储中；收藏、点赞和关注属于本实验中的设备侧交互状态，保存在本地缓存中。这样的划分减少了不必要的云端写操作，也能让交互反馈更加及时。

### 4. 瀑布流布局如何实现？

项目没有引入额外布局库，而是将筛选后的作品按索引奇偶拆分到左右两列，再由 WXML 分别渲染。该方法实现简单，适合当前实验规模；如果作品数量进一步增加，可以改为根据左右列高度动态分配，以获得更均衡的瀑布流效果。

## 五、收获与建议

通过本实验，我熟悉了微信小程序云开发的基本流程，掌握了云环境初始化、云函数调用、云存储上传、云数据库增删查以及本地缓存的使用方法。相比只使用本地数据的页面，图片分享社区需要同时处理用户身份、文件上传、数据库记录和页面状态同步，因此对异步流程和异常处理提出了更高要求。

在界面实现方面，我进一步掌握了小程序页面跳转、条件渲染、列表渲染、双列布局、图片预览和微信分享等功能。通过将首页、发布页、详情页和个人主页拆分，可以让各页面职责更清晰，也方便后续维护。

后续可以继续完善以下功能：接入服务器端点赞和收藏数据，实现多设备同步；增加分页加载和图片压缩，降低大量图片加载时的网络压力；增加评论、举报和内容审核；进一步优化瀑布流布局和图片加载占位效果，使应用更接近实际的图片社区产品。
